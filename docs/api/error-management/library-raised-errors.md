# Library-Raised Errors

These are the reasons the library raises by itself, without the database saying anything: a query it refuses, a value it can't convert, a transaction used in the wrong way. Each row says what the reason means, what causes it, and how it arrives. For a code or a message of the database, go to the page of [your database](overview.md#where-to-find-a-reason-or-a-code).

Some of these reasons can also come from the driver when it reports the same condition. Those have `databaseErrorCode` and the rest of the database metadata, and the code is in the page of your database.

Unless a row says otherwise, the reason arrives through the promise of the `execute*` method, inside a `TsSqlQueryExecutionError`. "Thrown at the call" means that the method you called throws a `TsSqlProcessingError`, with no promise involved. [How each error arrives](overview.md#how-each-error-arrives) has the whole picture.

!!! note "Mocks go through the same conversions as a driver"

    `INVALID_MOCKED_VALUE` checks only the shape of what the function given to `MockQueryRunner` returns (a plain object for a single-row select, an array of plain objects for a many-row select, a number for affected-row counts). After that check, the value goes through the same conversions as the response of a real driver. A row that omits a column the `select` projects as required gives `MANDATORY_VALUE_NOT_RECEIVED_FROM_DATABASE`, a value with the wrong type gives `INVALID_VALUE_RECEIVED_FROM_DATABASE`, and a JSON aggregate that can't be parsed gives `INVALID_JSON_RECEIVED_FROM_DATABASE`. To fix it in a test, include every projected column in the mocked row, or return `[]` or `undefined` when the test only checks the SQL.

### The database rolled back the transaction

Some errors make the database roll back the whole transaction by itself. When your code catches such an error and goes on, the next statements and the commit can't save anything. So the library rejects them with `TRANSACTION_ERROR` and `transactionErrorType: 'transaction rolled back'`, with no database code. [When the database rolls back the transaction](../../queries/transaction.md#when-the-database-rolls-back-the-transaction) says when this happens on each database.

The error of the statement that ended the transaction is not in `cause`, but one level below:

| Field | What it has |
| --- | --- |
| `error` | The `TsSqlQueryExecutionError` you caught, with the reason `TRANSACTION_ERROR` |
| `error.cause` | A `TsSqlError` with the same reason |
| `error.cause.cause` | The error of the driver for the statement that ended the transaction |
