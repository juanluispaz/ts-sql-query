# Mapping

## Mapping the tables

In order to use the tables in queries, you need to map it in your system. To do it, you need to extend the table class that receives two generic arguments, the first one is the connection class, and the second one is a unique name for the table in your system.

```ts
import { Table } from "ts-sql-query" // or "ts-sql-query/Table";

const tCompany = new class TCompany extends Table<DBConnection, 'TCompany'> {
    id = this.autogeneratedPrimaryKey('id', 'int');
    name = this.column('name', 'string');
    parentId = this.optionalColumn('parent_id', 'int');
    ubicationLatitude = this.optionalColumn('ubication_latitude', 'string');
    ubicationLongitude = this.optionalColumn('ubication_longitude', 'string');
    ubicationComment = this.optionalColumn('ubication_comment', 'string');
    constructor() {
        super('company'); // table name in the database
    }
}();
```

!!! warning

    The constructor of a table must expect no arguments.

## Kinds of columns

Each column is declared with the method that says what it is in the database, and that decides what an insert and an update can do with it:

| Method | Admits `null` | In an insert | In an update |
|:-------|:--------------|:-------------|:-------------|
| `column` | no | required | can be set |
| `optionalColumn` | yes | can be omitted (it is left `null`) | can be set, also to `null` |
| `columnWithDefaultValue` | no | can be omitted (the database gives it its default value) | can be set |
| `optionalColumnWithDefaultValue` | yes | can be omitted (the database gives it its default value) | can be set, also to `null` |
| `primaryKey` | no | required | can be set |
| `autogeneratedPrimaryKey` | no | can be omitted (the database generates it); `returningLastInsertedId()` returns it | can be set |
| `autogeneratedPrimaryKeyBySequence` | no | can be omitted (`ts-sql-query` writes the next value of the sequence); `returningLastInsertedId()` returns it | can be set |
| `computedColumn` / `optionalComputedColumn` | no / yes | can't be set: the database computes it | can't be set |
| `virtualColumnFromFragment` / `optionalVirtualColumnFromFragment` | no / yes | can't be set: it isn't a column of the database (see [Virtual columns](#virtual-columns)) | can't be set |

All of them can be read in a select. Setting a column that can't be set, or leaving out a required one, is a compilation error.

```ts
import { Table } from "ts-sql-query" // or "ts-sql-query/Table";

const tProduct = new class TProduct extends Table<DBConnection, 'TProduct'> {
    id = this.autogeneratedPrimaryKey('id', 'int');
    code = this.column('code', 'string');
    name = this.column('name', 'string');
    description = this.optionalColumn('description', 'string');
    createdAt = this.columnWithDefaultValue('created_at', 'localDateTime');
    discontinuedAt = this.optionalColumnWithDefaultValue('discontinued_at', 'localDateTime');
    priceWithTax = this.computedColumn('price_with_tax', 'double');
    upperName = this.virtualColumnFromFragment('string', (fragment) => fragment.sql`upper(${this.name})`);
    constructor() {
        super('product'); // table name in the database
    }
}();

// Only the required columns: id, created_at and discontinued_at are left to the database
const productId = await connection.insertInto(tProduct).set({
        code: 'P-001',
        name: 'Pen'
    })
    .returningLastInsertedId()
    .executeInsert();
```

The executed query is:

=== "MariaDB"
    ```mariadb
    insert into product (code, name)
    values (?, ?)
    returning id
    ```
=== "MySQL"
    ```mysql
    insert into product (`code`, `name`)
    values (?, ?)
    ```
=== "Oracle"
    ```oracle
    insert into product (code, name)
    values (:0, :1)
    returning id into :2
    ```
===+ "PostgreSQL"
    ```postgresql
    insert into product (code, name)
    values ($1, $2)
    returning id
    ```
=== "SQLite"
    ```sqlite
    insert into product (code, name)
    values (?1, ?2)
    returning id
    ```
=== "SQL Server"
    ```sqlserver
    insert into product (code, name)
    output inserted.id
    values (@0, @1)
    ```

The parameters are: `[ 'P-001', 'Pen' ]`

The result type is:
```tsx
const productId: number
```

### Primary key generated by a sequence

On [MariaDB](supported-databases/mariadb.md), [Oracle](supported-databases/oracle.md), [PostgreSQL](supported-databases/postgresql.md) and [SQL Server](supported-databases/sqlserver.md), `autogeneratedPrimaryKeyBySequence(name, sequenceName, type)` declares a primary key whose value comes from a sequence: an insert that leaves it out gets the next value of the sequence written by `ts-sql-query`.

```ts
const tInvoice = new class TInvoice extends Table<DBConnection, 'TInvoice'> {
    id = this.autogeneratedPrimaryKeyBySequence('id', 'invoice_seq', 'int');
    customerId = this.column('customer_id', 'int');
    constructor() {
        super('invoice'); // table name in the database
    }
}();

const invoiceId = await connection.insertInto(tInvoice).set({
        customerId: 1
    })
    .returningLastInsertedId()
    .executeInsert();
```

The executed query is:

=== "MariaDB"
    ```mariadb
    insert into invoice (id, customer_id)
    values (nextval(invoice_seq), ?)
    returning id
    ```
=== "MySQL"
    ```mysql
    -- MySQL doesn't have sequences
    ```
=== "Oracle"
    ```oracle
    insert into invoice (id, customer_id)
    values (invoice_seq.nextval, :0)
    returning id into :1
    ```
===+ "PostgreSQL"
    ```postgresql
    insert into invoice (id, customer_id)
    values (nextval('invoice_seq'), $1)
    returning id
    ```
=== "SQLite"
    ```sqlite
    -- SQLite doesn't have sequences
    ```
=== "SQL Server"
    ```sqlserver
    insert into invoice (id, customer_id)
    output inserted.id
    values (next value for invoice_seq, @0)
    ```

The parameters are: `[ 1 ]`

The result type is:
```tsx
const invoiceId: number
```

## Mapping the views

In order to use the views in queries, you need to map it in your system. To do it, you need to extend the view class that receives two generic arguments, the first one is the connection class, and the second one is a unique name for the view in your system.

```ts
import { View } from "ts-sql-query" // or "ts-sql-query/View";

const vCustomerAndCompany = new class VCustomerAndCompany extends View<DBConnection, 'VCustomerAndCompany'> {
    companyId = this.column('company_id', 'int');
    companyName = this.column('company_name', 'string');
    customerId = this.column('customer_id', 'int');
    customerFirstName = this.column('customer_first_name', 'string');
    customerLastName = this.column('customer_last_name', 'string');
    customerBirthday = this.optionalColumn('customer_birthday', 'localDate');
    constructor() {
        super('customer_company'); // view name in the database
    }
}();
```

!!! warning

    The constructor of a view must expect no arguments.

## Mapping constant values as view

You can use a set of data a a view made of constant values that will be executed in a query. To do it, you need to extend the Values class that receives two generic arguments, the first one is the connection class, and the second one is a unique name for the view in your query.

```ts
import { Values } from "ts-sql-query" // or "ts-sql-query/Values";

async function yourBusinessLogic() {
    class VCustomerForUpdate extends Values<DBConnection, 'customerForUpdate'> {
        id = this.column('int')
        firstName = this.column('string')
        lastName = this.column('string')
    }
    const customerForUpdate = Values.create(VCustomerForUpdate, 'customerForUpdate', [
        // Include your constant data here, it can be several records but must contains at least one.
        { 
            id: 1,
            firstName: 'First Name',
            lastName: 'Last Name'
        }
    ])
    // Use customerForUpdate as a view in your query
}
```

!!! warning

    - Do not provide or implement a constructor
    - The Values class is similar to the View class, with the difference the functions that allows to create the columns doesn't receive the column name.
    - Always create it using `Values.create`
    - This is supported by [PostgreSQL](../configuration/supported-databases/postgresql.md), [SQL Server](../configuration/supported-databases/sqlserver.md), [SQLite](../configuration/supported-databases/sqlite.md), [Oracle](../configuration/supported-databases/oracle.md), [MariaDB](../configuration/supported-databases/mariadb.md), and [MySQL](../configuration/supported-databases/mysql.md). On Oracle, the `Values` view can be used in `select`/join contexts; combining it with `update.from(...)` / `deleteFrom.using(...)` is rejected at compile time because Oracle's SQL does not support those clauses. MariaDB and MySQL support both, driving them through their multi-table `UPDATE` / `DELETE`.
    - In [PostgreSQL](../configuration/supported-databases/postgresql.md) the values included in the query will be forced to generate the type cast; ensure your custom types have a valid type cast. See [Column types](column-types.md)
    - In [MySQL](../configuration/supported-databases/mysql.md) the table value constructor is emitted using the `VALUES ROW(...)` row syntax MySQL requires; MariaDB uses the SQL-standard `VALUES (...)` form.
    - In [Oracle](../configuration/supported-databases/oracle.md), the generated SQL uses the standard `VALUES` table constructor on Oracle Database 23ai (`compatibilityVersion >= 23_004_000`) and falls back to a `select ... from dual union all` emulation on older versions. See [Compatibility version](../configuration/supported-databases/oracle.md#compatibility-version) for details.

## Grouping columns

The columns of a table, view or [constant values](#mapping-constant-values-as-view) can be grouped in an object, when some columns belong together; for example, the two columns of a coordinate. A group is a plain object, and it can contain other groups.

```ts
const tCompany = new class TCompany extends Table<DBConnection, 'TCompany'> {
    id = this.autogeneratedPrimaryKey('id', 'int');
    name = this.column('name', 'string');
    ubication = {
        latitude: this.optionalColumn('ubication_latitude', 'string').asRequiredInOptionalObject(),
        longitude: this.optionalColumn('ubication_longitude', 'string').asRequiredInOptionalObject(),
        comment: this.optionalColumn('ubication_comment', 'string'),
    };
    constructor() {
        super('company');
    }
}();
```

A column in a group is used as any other column, and the whole group can be selected, following the [rules of the nested objects](../queries/complex-projections.md#rules-for-nested-object-projections):

```ts
const company = await connection.selectFrom(tCompany)
    .where(tCompany.ubication.latitude.isNotNull())
    .select({ id: tCompany.id, ubication: tCompany.ubication })
    .executeSelectMany();
```

When a row is written, the values have the shape of the definition:

```ts
await connection.insertInto(tCompany)
    .set({ name: 'ACME', ubication: { latitude: '40.4', longitude: '-3.7' } })
    .executeInsert();

await connection.update(tCompany)
    .set({ ubication: { comment: 'Main office' } })
    .where(tCompany.id.equals(10))
    .executeUpdate();
```

The rules of a group when it's written are:

- A group is required in an insert when it has a required column, and then that column is required in the group. In an update, any column of a group can be left out.
- A column marked with `asRequiredInOptionalObject` is required when the group is provided, in the same way that the group doesn't exist without it when it's read.
- A group without value (`null` or `undefined`) is every one of its columns without value: `set({ ubication: null })` sets all its columns to null, and `setIfValue({ ubication: null })` ignores them. A group with a required column doesn't accept it.

The methods that receive the name of a column, like `ignoreIfSet`, `keepOnly` or `disallowIfSet`, accept the name of a group, meaning all its columns, and the path of a column in a group:

```ts
const query = connection.update(tCompany)
    .dynamicSet()
    .set(values)
    .keepOnly('name', 'ubication.comment')
    .where(tCompany.id.equals(10));
```

A [shape](../queries/shapes.md#columns-in-a-group) names a column in a group by its path too.

!!! note

    Only a plain object with at least one column is a group: anything else in the class, like a method or an object with other values, is not taken as part of the columns. The value of a column can be an object too (a custom type with a json value, for instance), because it's the definition that says what is a group. As with the [alias](../queries/complex-projections.md#nested-object-projections), the types reach up to the fifth level.

## Virtual columns

You can create virtual columns in a table or view, where the column doesn't exist in the database, but it is expanded during the query construction. You can create a property in your table or view assigning any computation over an already existing column to create a direct virtual column; or, you can call the `optionalVirtualColumnFromFragment` method to create a column from a SQL fragment.

```ts
import { Table } from "ts-sql-query" // or "ts-sql-query/Table";

const tCustomer = new class TCustomer extends Table<DBConnection, 'TCustomer'> {
    id = this.autogeneratedPrimaryKey('id', 'int');
    firstName = this.column('first_name', 'string');
    lastName = this.column('last_name', 'string');
    birthday = this.optionalColumn('birthday', 'localDate');
    companyId = this.column('company_id', 'int');

    // Direct virtual column
    name = this.firstName.concat(' ').concat(this.lastName);

    // Virtual column from a sql fragment
    age = this.optionalVirtualColumnFromFragment('int', (fragment) => {
        return fragment.sql`calculateAge(${this.birthday})`
    });

    constructor() {
        super('customer'); // table name in the database
    }
}();
```

!!! tip

    You can use a virtual column from a SQL fragment to call a function that returns a value, like in this example.

When you use in a query, the virtual column definition is expanded in the generated SQL.

```ts
const customersWithAge = connection.selectFrom(tCustomer)
    .select({
        id: tCustomer.id,
        name: tCustomer.name,
        age: tCustomer.age,
    })
    .executeSelectMany();
```

The executed query is:

=== "MariaDB"
    ```mariadb
    select 
        id as id, 
        concat(first_name, ?, last_name) as name, 
        calculateAge(birthday) as age 
    from customer
    ```
=== "MySQL"
    ```mysql
    select 
        id as id, 
        concat(first_name, ?, last_name) as `name`, 
        calculateAge(birthday) as age 
    from customer
    ```
=== "Oracle"
    ```oracle
    select 
        id as "id", 
        first_name || :0 || last_name as "name", 
        calculateAge(birthday) as "age" 
    from customer
    ```
===+ "PostgreSQL"
    ```postgresql
    select 
        id as id, 
        first_name || $1 || last_name as name, 
        calculateAge(birthday) as age 
    from customer
    ```
=== "SQLite"
    ```sqlite
    select 
        id as id, 
        first_name || ?1 || last_name as name, 
        calculateAge(birthday) as age 
    from customer
    ```
=== "SQL Server"
    ```sqlserver
    select 
        id as id, 
        first_name + @0 + last_name as name, 
        calculateAge(birthday) as age 
    from customer
    ```

The parameters are: `[ " " ]`

The result type is:
```tsx
const customersWithAge: Promise<{
    id: number;
    name: string;
    age?: number;
}[]>
```

## Creating methods that allows to call a procedure

```ts
import { PostgreSqlConnection } from "ts-sql-query/connections/PostgreSqlConnection";

class DBConnection extends PostgreSqlConnection<'DBConnection'> { 
    myOwnProcedure(param1: number) {
        return this.executeProcedure('myOwnprocedure', [this.const(param1, 'int')]);
    }
}
```

Executing the procedure:
```ts
const result = connection.myOwnProcedure(10);
```

The executed query is:

=== "MariaDB"
    ```mariadb
    call myOwnprocedure(?)
    ```
=== "MySQL"
    ```mysql
    call myOwnprocedure(?)
    ```
=== "Oracle"
    ```oracle
    begin myOwnprocedure(:0); end;
    ```
===+ "PostgreSQL"
    ```postgresql
    call myOwnprocedure($1::int4)
    ```
=== "SQLite"
    ```sqlite
    call myOwnprocedure(?1)
    ```
=== "SQL Server"
    ```sqlserver
    exec myOwnprocedure @0
    ```

The parameters are: `[ 10 ]`

The result type is a promise:
```tsx
const result: Promise<void>
```

## Creating methods that allows to call a function

```ts
import { PostgreSqlConnection } from "ts-sql-query/connections/PostgreSqlConnection";

class DBConnection extends PostgreSqlConnection<'DBConnection'> { 
    myOwnFunction(param1: number) {
        return this.executeFunction('myOwnFunction', [this.const(param1, 'int')], 'int', 'required');
    }
}
```

Executing the function:
```ts
const result = connection.myOwnFunction(10);
```

The executed query is:

=== "MariaDB"
    ```mariadb
    select myOwnFunction(?)
    ```
=== "MySQL"
    ```mysql
    select myOwnFunction(?)
    ```
=== "Oracle"
    ```oracle
    select myOwnFunction(:0) from dual
    ```
===+ "PostgreSQL"
    ```postgresql
    select myOwnFunction($1::int4)
    ```
=== "SQLite"
    ```sqlite
    select myOwnFunction(?1)
    ```
=== "SQL Server"
    ```sqlserver
    select myOwnFunction(@0)
    ```

The parameters are: `[ 10 ]`

The result type is a promise with the result returned by the function:
```tsx
const result: Promise<number>
```
