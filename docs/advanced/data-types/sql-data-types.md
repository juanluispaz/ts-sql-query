# The type of a column in the database

The [data type](../../configuration/data-types.md) of a column says what the value is in TypeScript and how the library converts it: an `int`, a `localDateTime`, an exact decimal of yours. It doesn't say what the column is in the database: an exact decimal can be a `numeric(18, 4)` or a `decimal(10, 2)`, a `string` a `varchar(50)` or an `nvarchar(max)`. The **SQL data type** says it: the family of the type in the database, with what refines it (the precision and the scale, the length, whether the text is national, the digits of the fraction of the seconds), and, if you want, its name in each database.

The library and the query runners use it where it gives a better query, and it saves giving a type per driver (`driverTypeOf` of a query runner) for what the SQL data type already says. Everything else works the same without it: it's optional, column by column.

Every type, function and property is listed in the [SQL data types API](../../api/sql-data-types.md).

## Declaring it

A SQL data type goes in the [type adapter](type-adapters.md) of the column, with `withSqlDataType`: without an adapter it creates one that only says the type; with one, it sets the type on that adapter and returns it. There are two ways to write the type: from its name, as the database writes it, or as the object.

### From the name of the type in the database (recommended)

Write the type as you see it in the database, `varchar(20)` or `numeric(18,4)`, and let the connection turn it into the SQL data type with `sqlDataTypeFrom`: it knows the names of its database, their aliases and what each one means, so what you write is what the database has, with less room for a mistake than writing the object by hand.

The tables are defined before any connection to the database exists, so this needs a connection of its own, made once, that executes nothing: an instance of your connection class (so it has the `compatibilityVersion` and the strategies of the real one) with a [`NoExecutionQueryRunner`](../../configuration/query-runners/general-purpose/NoExecutionQueryRunner.md), in a module your tables import:

```ts
import { NoExecutionQueryRunner } from "ts-sql-query"

// In a module of its own, like db/types.ts, exported: a connection that only reads the types of the database
const typesConnection = new DBConnection(new NoExecutionQueryRunner())
```

Then each column gives the name of its type:

```ts
import { DecimalsType, withSqlDataType } from "ts-sql-query"

abstract class PriceType extends DecimalsType<string, 'Price'> {
    static override readonly type = 'Price'
}

class TProduct extends Table<DBConnection, 'TProduct'> {
    id = this.autogeneratedPrimaryKey('id', 'int')
    price = this.column('price', PriceType, withSqlDataType(typesConnection.sqlDataTypeFrom('numeric(18,4)')))
    code = this.column('code', 'string', withSqlDataType(typesConnection.sqlDataTypeFrom('varchar(20)')))
    constructor() {
        super('product')
    }
}
```

`typesConnection.sqlDataTypeFrom('numeric(18,4)')` gives `{ family: 'exact numeric', precision: 18, scale: 4, native: { postgreSql: 'numeric(18,4)' } }`. A name the connection doesn't know gives a `'user-defined'` type with that name.

### As the object

The SQL data type can also be written as the object itself, with the [families](#the-families) below, when there's no connection at hand or the type is the same for several databases:

```ts
import { CustomBooleanTypeAdapter, DecimalsType, withSqlDataType } from "ts-sql-query"

abstract class PriceType extends DecimalsType<string, 'Price'> {
    static override readonly type = 'Price'
}

class TProduct extends Table<DBConnection, 'TProduct'> {
    id = this.autogeneratedPrimaryKey('id', 'int')
    price = this.column('price', PriceType, withSqlDataType({ family: 'exact numeric', precision: 18, scale: 4 }))
    code = this.column('code', 'string', withSqlDataType({ family: 'character string', length: 20, national: false }))
    active = this.column('active', 'boolean', withSqlDataType({ family: 'character string', length: 1, fixed: true }, new CustomBooleanTypeAdapter('Y', 'N')))
    constructor() {
        super('product')
    }
}
```

### What applies to both

Give each column a new adapter, as `new` in place does: `withSqlDataType` changes the adapter it receives, and an adapter that already says another type is rejected with `INVALID_CONFIGURATION`. To give it to a type adapter of yours, see [Type adapters → With the type of the column in the database](type-adapters.md#with-the-type-of-the-column-in-the-database).

A value compared with the column (`equals`, `in`, `between`, …) and the value given to it in an insert or an update take the SQL data type of the column, as they take its type adapter; so does a column of the result. A value computed from the column, like `name.concat('!')`, isn't a value of the column, so it doesn't take its SQL data type: its length, precision and scale are the ones each database computes, and most of them don't keep any. It keeps only what every database gives to its result: the text computed from a large object of text is a large object, like the `concat` of a `CLOB` on Oracle, and the one computed from a national text is national.

Like the type of a value, the SQL data type is two in the context of each transformation of a type adapter: the **original** one, `originalSqlDataType`, the one the adapter says, which never changes, and the **requested** one, `requestedSqlDataType`, the one the query runner receives, by default the original one. An adapter that sends a value as another type, like a date as its text, requests the type of what it sends with `setRequestedSqlDataType` (in `transformValueToDB` for the parameter, in `transformProjection` for the column of the result), and `resetRequestedSqlDataType()` requests the original one again.

## The families

| `family` | What it refines |
|---|---|
| `'exact numeric'` | `precision`, `scale`, `unsigned`, `bytes` (an integer: 1, 2, 3, 4 or 8) |
| `'approximate numeric'` | `precision` (binary digits: 24 single, 53 double) |
| `'boolean'` | — |
| `'character string'` | `length` (none: unlimited or the maximum), `lengthUnit` (`'characters'` or `'octets'`), `fixed`, `national`, `largeObject`, `characterSet`, `collation` |
| `'binary string'` | `length`, `fixed`, `largeObject`, `external` (Oracle `BFILE`) |
| `'datetime'` | `fields` (`'date'`, `'time'`, `'timestamp'`, `'year'`), `precision` (digits of the fraction of the seconds), `timeZone` |
| `'interval'` | `fields` (as the SQL standard names them: `'year'`, `'month'`, `'day'`, `'hour'`, `'minute'`, `'second'`, `'year to month'`, `'day to hour'`, `'day to minute'`, `'day to second'`, `'hour to minute'`, `'hour to second'`, `'minute to second'`; none: every field), `precision` |
| `'uuid'` | — |
| `'document'` | `format` (`'json'`, `'jsonb'`, `'xml'`, `'jsonpath'`); a description only: the library has no data type for a document |
| `'spatial'` | `model` (`'geometry'`, `'geography'`, `'planar'`, `'raster'`), `subtype`, `srid` |
| `'network address'` | `kind` (`'inet'`, `'cidr'`, `'macaddr'`, `'macaddr8'`), `ipFamily` (4 or 6) |
| `'bit string'` | `length`, `fixed` |
| `'enumeration'` | `values`, `name`, `multiple` (MySQL and MariaDB `SET`) |
| `'collection'` | `kind` (`'array'`, `'multiset'`, `'range'`, `'multirange'`, `'map'`), `of` (the SQL data type of its elements), `cardinality` |
| `'vector'` | `dimensions`, `element` (`'float32'`, `'float16'`, `'float64'`, `'int8'`, `'binary'`), `storage` (`'dense'`, `'sparse'`) |
| `'money'` | `scale` |
| `'text search'` | `kind` (`'document'`, `'query'`: PostgreSQL `tsvector`, `tsquery`) |
| `'row locator'` | `kind` (`'physical'`, `'universal'`: PostgreSQL `tid`, Oracle `ROWID`, `UROWID`) |
| `'row version'` | — (SQL Server `rowversion`) |
| `'variant'` | — (a value of any type: SQL Server `sql_variant`, Oracle `ANYDATA`, SQLite `ANY`) |
| `'hierarchy'` | — (SQL Server `hierarchyid`, PostgreSQL `ltree`) |
| `'system'` | `kind` (PostgreSQL `oid`, `xid`, `xid8`, `cid`, `pg_lsn`, `pg_snapshot`, `txid_snapshot`) |
| `'structured'` | `name`, `reference` (PostgreSQL composite types, Oracle object types and `REF`) |
| `'user-defined'` | `name`: a type of an extension or of yours that no family describes |

`timeZone` is the kind of the column (see [Time zones](../../configuration/time-zones.md)): `'none'`, a wall clock as it is (PostgreSQL `timestamp`, MySQL `DATETIME`, SQL Server `datetime2`); `'session'`, converted with the zone of the session (MySQL and MariaDB `TIMESTAMP`, Oracle `TIMESTAMP WITH LOCAL TIME ZONE`); `'instant'`, one normalized instant (PostgreSQL `timestamptz`); `'kept'`, each value with its zone (SQL Server `datetimeoffset`, Oracle `TIMESTAMP WITH TIME ZONE`).

Every family also takes `domain`, the name of the domain the column is declared with (the family is the type the domain is over), and `native`, the name of the type in each database, as it's written there (`{ sqlServer: 'datetime2(3)', oracle: 'TIMESTAMP(3)' }`): the connection of a database uses its own as it is; one without it works from the family.

## The SQL data type of a data type

The class of a data type says what its values are in the database, in its static `sqlDataType`: `IntType.sqlDataType`. The query runners send and read every value by the one of its data type, also a constant or a computed value like `price.add(1)` or `name.concat('!')`, and use the one of the column, when it describes the value, for what only the column says (the length of a text, a large object, the native name). They are two things apart, and the context has both: `originalSqlDataType` and `requestedSqlDataType` are the one declared (by the type adapter of the column, or requested with `setRequestedSqlDataType`), `undefined` when none is, and `originalType.sqlDataType` and `requestedType.sqlDataType` the one of the data type:

| Data type | Its SQL data type |
|---|---|
| `boolean` | `{ family: 'boolean' }` |
| `int`, `IntegersType` | `{ family: 'exact numeric', scale: 0, bytes: 4 }` |
| `bigint` | `{ family: 'exact numeric', scale: 0, bytes: 8 }` |
| `double`, `RealsType` | `{ family: 'approximate numeric', precision: 53 }` |
| `stringDecimal`, `dnumDecimal`, `DecimalsType` | `{ family: 'exact numeric' }` |
| `ScaledBigIntsType` of a scale, like `scaledBigIntType(2)` | `{ family: 'exact numeric', scale: 2 }` |
| `string` | `{ family: 'character string' }` |
| `uuid`, `UuidsType` | `{ family: 'uuid' }` |
| `localDate`, `LocalDatesType` | `{ family: 'datetime', fields: 'date' }` |
| `localTime`, `LocalTimesType` | `{ family: 'datetime', fields: 'time' }` |
| `localDateTime`, `LocalDateTimesType` | `{ family: 'datetime', fields: 'timestamp' }` |
| `EnumType`, `EqualableType`, `ComparableType`, `AdditiveType`, `MultipliableType`, `DivisibleType` | none: only you know what the value is, and it's sent as its value in JavaScript |

A class that extends a data type can give its own, like `static override readonly sqlDataType: SqlDataType = { family: 'exact numeric', precision: 30, scale: 0 }` for an integer of 30 digits: the query runners send and read its values by it without knowing the class.

The SQL data type of a column describes the value when it is of the family of the one of the data type: the same family for a boolean, a uuid, a date, a time or a timestamp; any number or a money for a number; any family but a number, a boolean, a date, a time or a binary for a text; any for a type without one. When a type adapter requests another type for the value (`setRequestedType`), the one of the column describes it or not by the same rule: a date sent as its text is sent as a text.

### A type the database emulates

Where a database has no type of its own for a value, the library keeps it in another, by the strategy of the connection: a uuid as a `char(36)` or a `binary(16)` on MySQL and MariaDB, as a `RAW(16)` on Oracle, as a `TEXT` or a `BLOB` on SQLite; a boolean as a `NUMBER(1)` on Oracle; a date or a time as a text or a number on SQLite. The SQL data type of a data type says what the value is (`{ family: 'uuid' }`), and the connection writes it as its strategy keeps it (`nativeSqlDataTypeOf` gives that type). The SQL data type of such a column, read from the catalogue (`sqlDataTypeFrom('char(36)')` for a uuid column), says how the database keeps the value, not what it is: it doesn't describe the value, and changes nothing of the query, which is the same as without it.

## How a value is sent to the database

Each parameter of a query goes with its type, the one requested for it: by default the type of its column or value, or the one a type adapter requests with `setRequestedType`, like a `string` for a date sent as its text. That type decides which SQL type the parameter has in the databases where the library declares one:

| Type | PostgreSQL type, where the query needs one | SQL Server parameter type |
|---|---|---|
| `boolean` | `bool` | `bit` |
| `int`, `IntegersType` of 4 bytes, its default | `int4` | `int` |
| `bigint`, `IntegersType` of 8 bytes | `int8` | `bigint` |
| `double`, `RealsType` | `float8` | `float` |
| `stringDecimal`, `dnumDecimal`, `DecimalsType`, `ScaledBigIntsType` | `numeric` | `nvarchar`, the text |
| `string` | `text` | `nvarchar` |
| `uuid`, `UuidsType` | `uuid` | `uniqueidentifier` |
| `localDate`, `LocalDatesType` | `date` | `date` |
| `localTime`, `LocalTimesType` | `time` | `time` |
| `localDateTime`, `LocalDateTimesType` | `timestamp` | `datetime2` |
| A type of yours whose family converts nothing, like `EnumType`, `EqualableType` or `ComparableType` | By the value: `int4` or `int8` for a whole number, `float8` for one with decimals, `int8` for a `bigint`, and none otherwise | By the value, and a text always as `nvarchar` |

PostgreSQL gets the type only where it can't tell it from the rest of the query, like a constant selected on its own or a row of [`Values`](../../configuration/mapping.md#mapping-constant-values-as-view). How it gets it depends on the query runner: `pg` and Bun SQL write it as a cast in the SQL (`select $1::int4 as result`); postgres.js and PGlite send the parameter with its type, and the SQL has no cast (`select $1 as result`). A `null` of one of these types is a parameter too, with its type: `$1::int4` with the parameter `null` on `pg`. Oracle declares it for a `null` of a number, a date or a time, and for a date or a time returned with `returning`: `NUMBER` or `TIMESTAMP`, as the driver sends their values. On MariaDB, MySQL and SQLite, and on Oracle for the rest, the driver sends each value as JavaScript gives it.

So the type also says how big the value can be in the database: an integer of yours is a 32-bit integer, like an `int`, unless its class says another SQL data type, like 64 bits; a `RealsType` is a floating point number, and an exact decimal a [`DecimalsType`](../../configuration/data-types.md#exact-decimals).

For a type the library doesn't know, like an enum of the database, say its SQL data type in its class ([The SQL data type of a data type](#the-sql-data-type-of-a-data-type)). The query runners of postgres.js, PGlite, SQL Server and Oracle also take `driverTypeOf`, a function that gives the type of the driver a parameter is sent with, for what only that driver has; each query runner's page has its shape.

## What the library does with it

| Database | With the SQL data type of the column |
|---|---|
| SQL Server | A text of a `character string` with `national: false` (a `varchar` or a `char` column) is sent as a `varchar` of the length of the column, a `varchar(max)` when it's longer, instead of an `nvarchar`. Compared with an `nvarchar`, SQL Server converts a `varchar` column, and with a SQL collation, like the default `SQL_Latin1_General_CP1_CI_AS`, it reads its whole index; as a `varchar` it seeks it. A text with a character outside ASCII is still sent as an `nvarchar`, which keeps it: as a `varchar` the driver would write it in the code page of the database, and a character it lacks would become `?`, also for a column of a UTF-8 collation. A date and time of a `datetime` or a `smalldatetime` column is sent as one, instead of a `datetime2`: compared with a `datetime2`, SQL Server converts the column with its exact fraction of 1/300 of a second, and an equality doesn't find a value with milliseconds (`10:00:00.123`) |
| Oracle | The `returning` of a `character string` that is a `largeObject` (a `CLOB`, an `NCLOB` with `national`) is received whole (without it, a text longer than 4000 bytes is rejected by Oracle, ORA-22835); one of a known `length` is received in a buffer of that length. An object of a `JSON` column (`{ family: 'document', format: 'json' }`), the value of a type of yours, is sent as a JSON; without it, the driver rejects an object |
| PostgreSQL | Where PostgreSQL needs the type of a parameter (a constant selected on its own, a value in a `coalesce`, a fragment), it gets the type of its SQL data type, without the precision or the length that would round or cut it (`numeric(18, 4)` is a `numeric`, `varchar(20)` a `varchar`, and `char(5)` a `bpchar`, the same type of any length: a `char` without its length would be of one character): also a type the library doesn't know, like a `jsonb`, an `inet` or an enum of the database (`{ family: 'enumeration', name: 'mood' }`). `pg` and Bun SQL write it as a cast (`$1::jsonb`); postgres.js and PGlite send the parameter with the oid of the type when it has a fixed one, and with the one their `driverTypeOf` gives for a type whose oid is the one of each database, like an enum |
| MariaDB, MySQL, SQLite | Nothing yet: the query runner receives it, so a query runner of yours can read it in [the context of the query](../running-queries/query-execution-metadata.md) (`originalSqlDataType` and `requestedSqlDataType` of each parameter and of each column of the result) |

With the SQL data type of the data type of a value, the query runners choose the type each value is sent with, where the driver or the database needs one, and how a column of the result is read: a boolean, a number, a text, a uuid, a date or a time goes with the type of the database of its family (an integer of up to 4 bytes as an `int4`, an `Int` or a `NUMBER`, one of 8 as an `int8`, a `BigInt` or a `NUMBER`, another exact number as a `numeric`, a text or a `NUMBER`). An exact number sent as its text, like a decimal, is cast to a decimal of its digits on MySQL, MariaDB and SQL Server, and checked against the widest decimal of the database. An exact number that isn't an integer of up to 4 bytes is read as its text on Oracle, so it keeps every digit, and one that isn't an integer of a fixed number of bytes is written as its text in a column of the result on SQL Server.

A type `driverTypeOf` of a query runner gives wins over the SQL data type. A SQL data type never cuts a value: a value is sent with the type of the column only where it fits in it.

### A date and time without zone

A `localDateTime` or an `instant` can be kept in a column with zone (a PostgreSQL `timestamptz`, a SQL Server `datetimeoffset`, an Oracle `TIMESTAMP WITH TIME ZONE`) or in one without it. Without a declaration the library doesn't know which, so where it needs the date and time of the value in the zone of the database, or in UTC, it writes the conversion that a column with zone needs: `::timestamp` on PostgreSQL, `switchoffset(…, '+00:00')` on SQL Server, `at local` on Oracle. On a column without zone that conversion changes nothing in the value, but on SQL Server and Oracle the database can no longer use an index of the column to find the rows.

Declare the column with `timeZone: 'none'`, from the name of its type (`sqlDataTypeFrom('datetime2')`, `sqlDataTypeFrom('timestamp')`) or as the object, and the library writes it as it is: in `toPlainDateTime()` of a `localDateTime` or an `instant`, in the arithmetic of an `instant`, in the parts of a `localDateTime` on SQL Server (`getHours()`, …) and in the conversions between them, which keep that declaration. Here `signedOffAt` is declared that way:

```ts
const tRelease = new class TRelease extends Table<DBConnection, 'TRelease'> {
    id = this.autogeneratedPrimaryKey('id', 'int')
    version = this.column('version', 'string')
    signedOffAt = this.optionalColumn('signed_off_at', 'localDateTime', withSqlDataType({ family: 'datetime', fields: 'timestamp', timeZone: 'none' }))
    publishedAt = this.column('published_at', 'plainDateTime')
    constructor() {
        super('project_release')
    }
}()

const releases = await connection.selectFrom(tRelease)
    .where(tRelease.signedOffAt.toPlainDateTime().lessThan(tRelease.publishedAt))
    .select({
        version: tRelease.version,
        signedOffAt: tRelease.signedOffAt.toPlainDateTime(),
        signedOffHour: tRelease.signedOffAt.getHours(),
    })
    .orderBy('version')
    .executeSelectMany()
```

The executed query is:

=== "MariaDB"
    ```mariadb
    select 
        version as version, 
        signed_off_at as signedOffAt, 
        hour(signed_off_at) as signedOffHour 
    from project_release 
    where signed_off_at < published_at 
    order by version
    ```
=== "MySQL"
    ```mysql
    select 
        version as version, 
        signed_off_at as signedOffAt, 
        hour(signed_off_at) as signedOffHour 
    from project_release 
    where signed_off_at < published_at 
    order by version
    ```
=== "Oracle"
    ```oracle
    select 
        version as "version", 
        to_char(cast(signed_off_at as timestamp(9)), 'YYYY-MM-DD"T"HH24:MI:SS.FF9 BC', 'NLS_DATE_LANGUAGE=AMERICAN') as "signedOffAt", 
        extract(hour from signed_off_at) as "signedOffHour" 
    from project_release 
    where signed_off_at < published_at 
    order by "version"
    ```
===+ "PostgreSQL"
    ```postgresql
    select 
        version as version, 
        signed_off_at as "signedOffAt", 
        extract(hour from signed_off_at) as "signedOffHour" 
    from project_release 
    where signed_off_at < published_at 
    order by version
    ```
=== "SQLite"
    ```sqlite
    select 
        version as version, 
        signed_off_at as signedOffAt, 
        cast(strftime('%H', signed_off_at) as integer) as signedOffHour 
    from project_release 
    where signed_off_at < published_at 
    order by version
    ```
=== "SQL Server"
    ```sqlserver
    select 
        version as version, 
        signed_off_at as signedOffAt, 
        datepart(hour, signed_off_at) as signedOffHour 
    from project_release 
    where signed_off_at < published_at 
    order by version
    ```

The parameters are: `[]`

| version | signedOffAt | signedOffHour |
|---|---|---|
| `'0.9.0'` | `2024-02-28T09:00:00` | `9` |
| `'1.2.0'` | `2024-01-14T12:30:00` | `12` |

Without the declaration, the same query writes `signed_off_at::timestamp` on PostgreSQL, `cast(switchoffset(signed_off_at, '+00:00') as datetime2)` and `datepart(hour, switchoffset(signed_off_at, '+00:00'))` on SQL Server, and `cast(cast(signed_off_at as timestamp(9) with time zone) at local as timestamp(9))` on Oracle (see [From a `Date` to Temporal and back](../../configuration/dates-as-date.md#from-a-date-to-temporal-and-back)). MariaDB, MySQL and SQLite write the column as it is either way.

On Oracle a `DATE`, declared with `precision: 0` (`sqlDataTypeFrom('DATE')`), is written as `cast(<column> as timestamp(9))`: `extract` doesn't read the time of a `DATE`. On SQL Server the arithmetic of an `instant` converts a column to a `datetime2` unless it is declared a `datetime2(7)`, so that it keeps every digit Temporal has. Declare `timeZone: 'none'` only on a column that really keeps no zone: on one that keeps it, the date and time would be the ones of the offset each value was stored with.

## The types of a database

Each connection converts the names of the types of its database to SQL data types and back, with `sqlDataTypeFrom` and `nativeSqlDataTypeOf`. `sqlDataTypeFrom` reads a type as the catalogue of the database writes it (`numeric(18,4)`, `character varying(20)`, `VARCHAR2(50 CHAR)`), aliases accepted, and keeps that name as its `native` one; `nativeSqlDataTypeOf` gives the name back, or one made from the family, or `undefined` when that database can't hold it, never another type. On PostgreSQL, a name made from the family is the one best known there: `int2`, `int4`, `int8`, `float4`, `float8`, `varchar(20)`, `char(5)`, `timestamptz`, `timetz`, and `boolean` for a boolean. It follows the `compatibilityVersion` of the connection (a type the version doesn't have gives `undefined`), and where the connection stores what the database lacks: a uuid as its `uuidStrategy` says (on Oracle a `RAW(16)` with the default strategy, a `VARCHAR2(36)` with `'string'`), a boolean of Oracle as its `booleanStorage` says (`NUMBER(1)` or `BOOLEAN`), a date of SQLite as its format says.

For a program that only needs the types, like a generator that reads the catalogue, give the connection a [`NoExecutionQueryRunner`](../../configuration/query-runners/general-purpose/NoExecutionQueryRunner.md): it executes nothing.

```ts
import { NoExecutionQueryRunner, withSqlDataType } from "ts-sql-query"
import { PostgreSqlConnection } from "ts-sql-query/postgresql"

class PostgreSql13Types extends PostgreSqlConnection<'PostgreSql13Types'> {
    protected override compatibilityVersion = 13_000_000
}

const types = new PostgreSql13Types(new NoExecutionQueryRunner())
const price = types.sqlDataTypeFrom('numeric(18,4)')
// { family: 'exact numeric', precision: 18, scale: 4, native: { postgreSql: 'numeric(18,4)' } }
const priceAdapter = withSqlDataType(price)
const days = types.nativeSqlDataTypeOf({ family: 'collection', kind: 'multirange', of: { family: 'datetime', fields: 'date' } })
// undefined: the multiranges came in PostgreSQL 14 (with 14 or later, 'datemultirange')
```

What a database keeps isn't always what was written: Oracle keeps an `INTEGER` as a `NUMBER(38, 0)`, MariaDB a `JSON` as a `LONGTEXT`, SQL Server a `datetime` with its own name. `sqlDataTypeFrom` gives what the database keeps; the name in `native` gives it back exactly.

On SQLite, `sqlDataTypeFrom` reads the six types of a `STRICT` table (`INTEGER`, `INT`, `REAL`, `TEXT`, `BLOB`, `ANY`) and, in a table that isn't `STRICT`, where a column can be declared with any name, the common names of the other databases (`VARCHAR(10)`, `DECIMAL(10, 2)`, `DATETIME`, `BOOLEAN`, `UUID`, …); any other name is a `'user-defined'` type. To read names of your own, override the method in your connection.
