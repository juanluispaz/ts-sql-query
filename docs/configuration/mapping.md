# Mapping

To use a table or a view in a query, you describe it in TypeScript: a class with one property for each column. This page has how to map tables and views, the kinds of columns there are, how to group them, how to add columns computed in the query, and how to call the procedures and functions of your database. The [types of the columns](column-types.md) have their own page.

## Mapping the tables

A table is a class that extends `Table`, with two generic arguments: your [connection class](connection.md#defining-the-connection-object), and a unique name for the table in your system. Each property is a column, with the name it has in the database and its [type](column-types.md).

```ts
import { Table } from "ts-sql-query" // or "ts-sql-query/Table";

const tCompany = new class TCompany extends Table<DBConnection, 'TCompany'> {
    id = this.autogeneratedPrimaryKey('id', 'int');
    name = this.column('name', 'string');
    parentId = this.optionalColumn('parent_id', 'int');
    ubicationLatitude = this.optionalColumn('ubication_latitude', 'string');
    ubicationLongitude = this.optionalColumn('ubication_longitude', 'string');
    ubicationComment = this.optionalColumn('ubication_comment', 'string');
    constructor() {
        super('company'); // table name in the database
    }
}();
```

!!! warning

    The constructor of a table must expect no arguments: the library creates new instances of the class, for example for an alias with `as`.

## Kinds of columns

Each column is declared with the method that says what it is in the database, and that decides what an insert and an update can do with it:

| Method | Admits `null` | In an insert | In an update |
|:-------|:--------------|:-------------|:-------------|
| `column` | no | required | can be set |
| `optionalColumn` | yes | can be omitted (it is left `null`) | can be set, also to `null` |
| `columnWithDefaultValue` | no | can be omitted (the database gives it its default value) | can be set |
| `optionalColumnWithDefaultValue` | yes | can be omitted (the database gives it its default value) | can be set, also to `null` |
| `primaryKey` | no | required | can be set |
| `autogeneratedPrimaryKey` | no | can be omitted (the database generates it); `returningLastInsertedId()` returns it | can be set |
| `autogeneratedPrimaryKeyBySequence` | no | can be omitted (`ts-sql-query` writes the next value of the sequence); `returningLastInsertedId()` returns it | can be set |
| `computedColumn` / `optionalComputedColumn` | no / yes | can't be set: the database computes it | can't be set |
| `virtualColumnFromFragment` / `optionalVirtualColumnFromFragment` | no / yes | can't be set: it isn't a column of the database (see [Virtual columns](#virtual-columns)) | can't be set |

All of them can be read in a select. Setting a column that can't be set, or leaving out a required one, is a compilation error.

```ts
import { Table } from "ts-sql-query" // or "ts-sql-query/Table";

const tProduct = new class TProduct extends Table<DBConnection, 'TProduct'> {
    id = this.autogeneratedPrimaryKey('id', 'int');
    code = this.column('code', 'string');
    name = this.column('name', 'string');
    description = this.optionalColumn('description', 'string');
    createdAt = this.columnWithDefaultValue('created_at', 'localDateTime');
    discontinuedAt = this.optionalColumnWithDefaultValue('discontinued_at', 'localDateTime');
    priceWithTax = this.computedColumn('price_with_tax', 'double');
    upperName = this.virtualColumnFromFragment('string', (fragment) => fragment.sql`upper(${this.name})`);
    constructor() {
        super('product'); // table name in the database
    }
}();

// Only the required columns: id, created_at and discontinued_at are left to the database
const productId = await connection.insertInto(tProduct).set({
        code: 'P-001',
        name: 'Pen'
    })
    .returningLastInsertedId()
    .executeInsert();
```

The executed query is:

=== "MariaDB"
    ```mariadb
    insert into product (code, name)
    values (?, ?)
    returning id
    ```
=== "MySQL"
    ```mysql
    insert into product (`code`, `name`)
    values (?, ?)
    ```
=== "Oracle"
    ```oracle
    insert into product (code, name)
    values (:0, :1)
    returning id into :2
    ```
===+ "PostgreSQL"
    ```postgresql
    insert into product (code, name)
    values ($1, $2)
    returning id
    ```
=== "SQLite"
    ```sqlite
    insert into product (code, name)
    values (?1, ?2)
    returning id
    ```
=== "SQL Server"
    ```sqlserver
    insert into product (code, name)
    output inserted.id
    values (@0, @1)
    ```

The parameters are: `[ 'P-001', 'Pen' ]`

The result type is:
```tsx
const productId: number
```

### Primary key generated by a sequence

A sequence is an object of the database that gives the next number of a series. On [MariaDB](supported-databases/mariadb.md), [Oracle](supported-databases/oracle.md), [PostgreSQL](supported-databases/postgresql.md) and [SQL Server](supported-databases/sqlserver.md), `autogeneratedPrimaryKeyBySequence(name, sequenceName, type)` declares a primary key whose value comes from a sequence: an insert that leaves it out gets the next value of the sequence written by `ts-sql-query`.

```ts
const tInvoice = new class TInvoice extends Table<DBConnection, 'TInvoice'> {
    id = this.autogeneratedPrimaryKeyBySequence('id', 'invoice_seq', 'int');
    customerId = this.column('customer_id', 'int');
    constructor() {
        super('invoice'); // table name in the database
    }
}();

const invoiceId = await connection.insertInto(tInvoice).set({
        customerId: 1
    })
    .returningLastInsertedId()
    .executeInsert();
```

The executed query is:

=== "MariaDB"
    ```mariadb
    insert into invoice (id, customer_id)
    values (nextval(invoice_seq), ?)
    returning id
    ```
=== "MySQL"
    ```mysql
    -- MySQL doesn't have sequences
    ```
=== "Oracle"
    ```oracle
    insert into invoice (id, customer_id)
    values (invoice_seq.nextval, :0)
    returning id into :1
    ```
===+ "PostgreSQL"
    ```postgresql
    insert into invoice (id, customer_id)
    values (nextval('invoice_seq'), $1)
    returning id
    ```
=== "SQLite"
    ```sqlite
    -- SQLite doesn't have sequences
    ```
=== "SQL Server"
    ```sqlserver
    insert into invoice (id, customer_id)
    output inserted.id
    values (next value for invoice_seq, @0)
    ```

The parameters are: `[ 1 ]`

The result type is:
```tsx
const invoiceId: number
```

## Mapping the views

A view is a class that extends `View`, with the same two generic arguments as a table. It can only be read, because `insertInto`, `update` and `deleteFrom` receive tables, so it has no primary keys or default values: its columns are declared with `column` and `optionalColumn`, and it can have [virtual columns](#virtual-columns).

```ts
import { View } from "ts-sql-query" // or "ts-sql-query/View";

const vCustomerAndCompany = new class VCustomerAndCompany extends View<DBConnection, 'VCustomerAndCompany'> {
    companyId = this.column('company_id', 'int');
    companyName = this.column('company_name', 'string');
    customerId = this.column('customer_id', 'int');
    customerFirstName = this.column('customer_first_name', 'string');
    customerLastName = this.column('customer_last_name', 'string');
    customerBirthday = this.optionalColumn('customer_birthday', 'localDate');
    constructor() {
        super('customer_company'); // view name in the database
    }
}();
```

!!! warning

    The constructor of a view must expect no arguments, for the same reason as a table.

## Grouping columns

The columns of a table, view or [constant values](#mapping-constant-values-as-view) can be grouped in an object, when some columns belong together; for example, the two columns of a coordinate. A group is a plain object, and it can contain other groups.

```ts
const tGroupedCompany = new class TGroupedCompany extends Table<DBConnection, 'TGroupedCompany'> {
    id = this.autogeneratedPrimaryKey('id', 'int');
    name = this.column('name', 'string');
    ubication = {
        latitude: this.optionalColumn('ubication_latitude', 'string').asRequiredInOptionalObject(),
        longitude: this.optionalColumn('ubication_longitude', 'string').asRequiredInOptionalObject(),
        comment: this.optionalColumn('ubication_comment', 'string'),
    };
    constructor() {
        super('company');
    }
}();
```

A column in a group is used as any other column, and the whole group can be selected, following the [rules of the nested objects](../queries/complex-projections.md#rules-for-nested-object-projections):

```ts
const company = await connection.selectFrom(tGroupedCompany)
    .where(tGroupedCompany.ubication.latitude.isNotNull())
    .select({ id: tGroupedCompany.id, ubication: tGroupedCompany.ubication })
    .executeSelectMany();
```

The executed query is:

=== "MariaDB"
    ```mariadb
    select 
        id as id, 
        ubication_latitude as `ubication.latitude`, 
        ubication_longitude as `ubication.longitude`, 
        ubication_comment as `ubication.comment` 
    from company 
    where ubication_latitude is not null
    ```
=== "MySQL"
    ```mysql
    select 
        id as id, 
        ubication_latitude as `ubication.latitude`, 
        ubication_longitude as `ubication.longitude`, 
        ubication_comment as `ubication.comment` 
    from company 
    where ubication_latitude is not null
    ```
=== "Oracle"
    ```oracle
    select 
        id as "id", 
        ubication_latitude as "ubication.latitude", 
        ubication_longitude as "ubication.longitude", 
        ubication_comment as "ubication.comment" 
    from company 
    where ubication_latitude is not null
    ```
===+ "PostgreSQL"
    ```postgresql
    select 
        id as id, 
        ubication_latitude as "ubication.latitude", 
        ubication_longitude as "ubication.longitude", 
        ubication_comment as "ubication.comment" 
    from company 
    where ubication_latitude is not null
    ```
=== "SQLite"
    ```sqlite
    select 
        id as id, 
        ubication_latitude as "ubication.latitude", 
        ubication_longitude as "ubication.longitude", 
        ubication_comment as "ubication.comment" 
    from company 
    where ubication_latitude is not null
    ```
=== "SQL Server"
    ```sqlserver
    select 
        id as id, 
        ubication_latitude as [ubication.latitude], 
        ubication_longitude as [ubication.longitude], 
        ubication_comment as [ubication.comment] 
    from company 
    where ubication_latitude is not null
    ```

The parameters are: `[]`

The result type is:
```tsx
const company: {
    id: number;
    ubication?: {
        latitude: string;
        longitude: string;
        comment?: string;
    };
}[]
```

When a row is written, the values have the shape of the definition:

```ts
const companyId = await connection.insertInto(tGroupedCompany)
    .set({ name: 'ACME', ubication: { latitude: '40.4', longitude: '-3.7' } })
    .returningLastInsertedId()
    .executeInsert();
```

The executed query is:

=== "MariaDB"
    ```mariadb
    insert into company (name, ubication_latitude, ubication_longitude) 
    values (?, ?, ?) 
    returning id
    ```
=== "MySQL"
    ```mysql
    insert into company (`name`, ubication_latitude, ubication_longitude) 
    values (?, ?, ?)
    ```
=== "Oracle"
    ```oracle
    insert into company (name, ubication_latitude, ubication_longitude) 
    values (:0, :1, :2) 
    returning id into :3
    ```
===+ "PostgreSQL"
    ```postgresql
    insert into company (name, ubication_latitude, ubication_longitude) 
    values ($1, $2, $3) 
    returning id
    ```
=== "SQLite"
    ```sqlite
    insert into company (name, ubication_latitude, ubication_longitude) 
    values (?1, ?2, ?3) 
    returning id
    ```
=== "SQL Server"
    ```sqlserver
    insert into company (name, ubication_latitude, ubication_longitude) output inserted.id 
    values (@0, @1, @2)
    ```

The parameters are: `[ 'ACME', '40.4', '-3.7' ]` (on Oracle: `[ 'ACME', '40.4', '-3.7', {'dir': 3003} ]`)

In an update, only the columns you give are written:

```ts
const updatedCompanies = await connection.update(tGroupedCompany)
    .set({ ubication: { comment: 'Main office' } })
    .where(tGroupedCompany.id.equals(10))
    .executeUpdate();
```

The executed query is:

=== "MariaDB"
    ```mariadb
    update company 
    set ubication_comment = ? 
    where id = ?
    ```
=== "MySQL"
    ```mysql
    update company 
    set ubication_comment = ? 
    where id = ?
    ```
=== "Oracle"
    ```oracle
    update company 
    set ubication_comment = :0 
    where id = :1
    ```
===+ "PostgreSQL"
    ```postgresql
    update company 
    set ubication_comment = $1 
    where id = $2
    ```
=== "SQLite"
    ```sqlite
    update company 
    set ubication_comment = ?1 
    where id = ?2
    ```
=== "SQL Server"
    ```sqlserver
    update company 
    set ubication_comment = @0 
    where id = @1
    ```

The parameters are: `[ 'Main office', 10 ]`

The rules of a group when it's written are:

- A group is required in an insert when it has a required column, and then that column is required in the group. In an update, any column of a group can be left out.
- A column marked with `asRequiredInOptionalObject` is required when the group is provided, in the same way that the group doesn't exist without it when it's read.
- A group without value (`null` or `undefined`) is every one of its columns without value: `set({ ubication: null })` sets all its columns to null, and `setIfValue({ ubication: null })` ignores them. A group with a required column doesn't accept it.

The methods that receive the name of a column, like `ignoreIfSet`, `keepOnly` or `disallowIfSet`, accept the name of a group, meaning all its columns, and the path of a column in a group:

```ts
const updatedRows = await connection.update(tGroupedCompany)
    .dynamicSet()
    .set({ name: 'ACME', ubication: { latitude: '40.4', comment: 'Main office' } })
    .keepOnly('name', 'ubication.comment')
    .where(tGroupedCompany.id.equals(10))
    .executeUpdate();
```

The executed query is:

=== "MariaDB"
    ```mariadb
    update company 
    set 
        name = ?, 
        ubication_comment = ? 
    where id = ?
    ```
=== "MySQL"
    ```mysql
    update company 
    set 
        `name` = ?, 
        ubication_comment = ? 
    where id = ?
    ```
=== "Oracle"
    ```oracle
    update company 
    set 
        name = :0, 
        ubication_comment = :1 
    where id = :2
    ```
===+ "PostgreSQL"
    ```postgresql
    update company 
    set 
        name = $1, 
        ubication_comment = $2 
    where id = $3
    ```
=== "SQLite"
    ```sqlite
    update company 
    set 
        name = ?1, 
        ubication_comment = ?2 
    where id = ?3
    ```
=== "SQL Server"
    ```sqlserver
    update company 
    set 
        name = @0, 
        ubication_comment = @1 
    where id = @2
    ```

The parameters are: `[ 'ACME', 'Main office', 10 ]`

A [shape](../queries/shapes.md#columns-in-a-group) names a column in a group by its path too.

!!! note

    Only a plain object with at least one column is a group: anything else in the class, like a method or an object with other values, is not taken as part of the columns. The value of a column can be an object too (a custom type with a json value, for instance), because it's the definition that says what is a group. As with the [alias](../queries/complex-projections.md#nested-object-projections), the types reach up to the fifth level.

## Virtual columns

A virtual column doesn't exist in the database: it's a computation over other columns, written in the query each time you use it. It's read like any other column, and it can't be written. There are two ways to create one in a table or a view:

- A property that assigns a computation over an existing column. Its type comes from the computation.
- `virtualColumnFromFragment` for a required value, or `optionalVirtualColumnFromFragment` for one that can have no value, which receive the type and a [SQL fragment](../queries/sql-fragments.md).

```ts
import { Table } from "ts-sql-query" // or "ts-sql-query/Table";

const tCustomer = new class TCustomer extends Table<DBConnection, 'TCustomer'> {
    id = this.autogeneratedPrimaryKey('id', 'int');
    firstName = this.column('first_name', 'string');
    lastName = this.column('last_name', 'string');
    birthday = this.optionalColumn('birthday', 'localDate');
    companyId = this.column('company_id', 'int');

    // Direct virtual column
    name = this.firstName.concat(' ').concat(this.lastName);

    // Virtual column from a sql fragment
    age = this.optionalVirtualColumnFromFragment('int', (fragment) => {
        return fragment.sql`calculateAge(${this.birthday})`
    });

    constructor() {
        super('customer'); // table name in the database
    }
}();
```

A virtual column from a fragment can call a function of your database, as `age` does here. When you use it in a query, its definition is written in the SQL:

```ts
const customersWithAge = connection.selectFrom(tCustomer)
    .select({
        id: tCustomer.id,
        name: tCustomer.name,
        age: tCustomer.age,
    })
    .executeSelectMany();
```

The executed query is:

=== "MariaDB"
    ```mariadb
    select 
        id as id, 
        concat(first_name, ?, last_name) as name, 
        calculateAge(birthday) as age 
    from customer
    ```
=== "MySQL"
    ```mysql
    select 
        id as id, 
        concat(first_name, ?, last_name) as `name`, 
        calculateAge(birthday) as age 
    from customer
    ```
=== "Oracle"
    ```oracle
    select 
        id as "id", 
        first_name || :0 || last_name as "name", 
        calculateAge(birthday) as "age" 
    from customer
    ```
===+ "PostgreSQL"
    ```postgresql
    select 
        id as id, 
        first_name || $1 || last_name as name, 
        calculateAge(birthday) as age 
    from customer
    ```
=== "SQLite"
    ```sqlite
    select 
        id as id, 
        first_name || ?1 || last_name as name, 
        calculateAge(birthday) as age 
    from customer
    ```
=== "SQL Server"
    ```sqlserver
    select 
        id as id, 
        first_name + @0 + last_name as name, 
        calculateAge(birthday) as age 
    from customer
    ```

The parameters are: `[ " " ]`

The result type is:
```tsx
const customersWithAge: Promise<{
    id: number;
    name: string;
    age?: number;
}[]>
```

## Mapping constant values as view

`Values` is a table whose rows come from your code: they travel in the query as parameters, and the query uses them as it uses any other table. It's the way to change several rows in one query, each with its own values, instead of sending one query per row: see [Bulk update](../queries/update.md#bulk-update) and [Bulk delete](../queries/delete.md#bulk-delete), which show it in a query.

You extend the class `Values`, with two generic arguments: your connection class, and a unique name for the view in your query.

```ts
import { Values } from "ts-sql-query" // or "ts-sql-query/Values";

async function yourBusinessLogic() {
    class VCustomerForUpdate extends Values<DBConnection, 'customerForUpdate'> {
        id = this.column('int')
        firstName = this.column('string')
        lastName = this.column('string')
    }
    const customerForUpdate = Values.create(VCustomerForUpdate, 'customerForUpdate', [
        // Your constant data: several rows, at least one
        { 
            id: 1,
            firstName: 'First Name',
            lastName: 'Last Name'
        }
    ])
    // Use customerForUpdate as a view in your query
}
```

Compared with a view:

- It has no constructor: create it always with `Values.create`, which receives the class, the name and the rows. With an empty list of rows, `Values.create` throws the error `CONSTANT_VALUES_VIEW_CANNOT_BE_EMPTY`.
- Its columns don't receive a name: they are created with `column`, `optionalColumn`, `virtualColumnFromFragment` and `optionalVirtualColumnFromFragment`.

Every database can use it in a select. What changes between them:

- **PostgreSQL**: the values are written with a cast, so [your custom types need a valid one](column-types.md#custom-types).
- **MySQL**: it needs MySQL 8.0.19. With a `compatibilityVersion` below `8_000_000`, [the query is rejected](supported-databases/mysql.md#compatibility-version).
- **Oracle**: below `compatibilityVersion` `23_004_000`, it's written with `select ... from dual union all` instead of `values`. In the `from` of an update and the `using` of a delete, the database rejects it.
- **MariaDB and MySQL**: in an update or a delete, they use their multi-table forms. On MariaDB that needs MariaDB 12.3, and [with Bun SQL it can't be used](query-runners/recommended/bun_sql_mysql.md).

## Using a sequence

On MariaDB, Oracle, PostgreSQL and SQL Server, you declare a sequence as a property of the connection, with the name it has in the database and the type of its values. Then `nextValue()` and `currentValue()` give a value to use in a query, like the value of a column in an insert. To fill the primary key on its own, you only need [`autogeneratedPrimaryKeyBySequence`](#primary-key-generated-by-a-sequence).

```ts
class DBConnection extends PostgreSqlConnection<'DBConnection'> {
    invoiceSeq = this.sequence('invoice_seq', 'int');
}
```

## Calling a stored procedure

`executeProcedure` is a protected method of the connection, so you write a method in your connection class for each procedure. It receives the name of the procedure and its parameters, as values like `this.const(...)`. SQLite has no stored procedures: the method exists, and the database rejects the statement.

```ts
import { PostgreSqlConnection } from "ts-sql-query/connections/PostgreSqlConnection";

class DBConnection extends PostgreSqlConnection<'DBConnection'> { 
    myOwnProcedure(param1: number) {
        return this.executeProcedure('myOwnprocedure', [this.const(param1, 'int')]);
    }
}
```

Executing the procedure:
```ts
const result = connection.myOwnProcedure(10);
```

The executed query is:

=== "MariaDB"
    ```mariadb
    call myOwnprocedure(?)
    ```
=== "MySQL"
    ```mysql
    call myOwnprocedure(?)
    ```
=== "Oracle"
    ```oracle
    begin myOwnprocedure(:0); end;
    ```
===+ "PostgreSQL"
    ```postgresql
    call myOwnprocedure($1::int4)
    ```
=== "SQLite"
    ```sqlite
    call myOwnprocedure(?1)
    ```
=== "SQL Server"
    ```sqlserver
    exec myOwnprocedure @0
    ```

The parameters are: `[ 10 ]`

The result type is a promise:
```tsx
const result: Promise<void>
```

## Calling a function of the database

`executeFunction` is also a protected method of the connection. It receives the name of the function, its parameters, the [type](column-types.md) of the result, and `'required'` or `'optional'`: with `'optional'` the result can be `null`. On SQLite, a function exists only if you register it in the driver.

```ts
import { PostgreSqlConnection } from "ts-sql-query/connections/PostgreSqlConnection";

class DBConnection extends PostgreSqlConnection<'DBConnection'> { 
    myOwnFunction(param1: number) {
        return this.executeFunction('myOwnFunction', [this.const(param1, 'int')], 'int', 'required');
    }
}
```

Executing the function:
```ts
const result = connection.myOwnFunction(10);
```

The executed query is:

=== "MariaDB"
    ```mariadb
    select myOwnFunction(?)
    ```
=== "MySQL"
    ```mysql
    select myOwnFunction(?)
    ```
=== "Oracle"
    ```oracle
    select myOwnFunction(:0) from dual
    ```
===+ "PostgreSQL"
    ```postgresql
    select myOwnFunction($1::int4)
    ```
=== "SQLite"
    ```sqlite
    select myOwnFunction(?1)
    ```
=== "SQL Server"
    ```sqlserver
    select myOwnFunction(@0)
    ```

The parameters are: `[ 10 ]`

The result type is a promise with the result returned by the function:
```tsx
const result: Promise<number>
```
