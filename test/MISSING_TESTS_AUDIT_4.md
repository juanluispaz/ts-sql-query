# Missing-tests audit — ROUND 4 (fresh, independent re-audit)

**This round was run as a clean-room pass.** Per request, it did **not** assume anything from rounds 1–3
([MISSING_TESTS_AUDIT.md](MISSING_TESTS_AUDIT.md) / [_2](MISSING_TESTS_AUDIT_2.md) / [_3](MISSING_TESTS_AUDIT_3.md))
beyond the **principles** fixed in the first audit — in particular it did **not** assume the round-3
"saturation, stop" verdict. Eight agents independently re-enumerated the public type surface from raw `src/`
reading and verified coverage **against the actual current test files**, ignoring the prior reports'
"covered/closed" claims. Findings were then adversarially verified.

**Principles (unchanged, from audit 1).** Unit = a *type-branch* (a distinction the type system makes even
when runtime JS is identical: overloads, union/optional params, per-type/per-arity arms, type transformations,
optionality/nullability propagation; canonical example: a method accepting `int` and `string` needs a test for
both). COVERED iff a `test/`-matrix test asserts that distinction — emitted SQL+params and/or resulting TS type
via `assertType<Exact<…>>`, or the produced runtime VALUE where the type promises one. Negative type tests
(`@ts-expect-error`/`types.negative`) + `src/queryRunners/` out of scope; coverage only against `test/`;
reference cell `postgres/newest/pg`, matrix symmetric; `void X`/`<any,any>`/signature-snapshot ≠ covered.

## Headline — the unanchored pass paid off

A fresh look found **~16 genuine type-branch gaps that three increasingly-narrow anchored rounds (and their
"saturation" critic) had missed** — e.g. the whole `AlwaysIfValueSource` operator surface, `optionalComputedColumn`,
the non-default `uuidStrategy` branches on Oracle/MySql/MariaDB, temporal/uuid nullable modifiers, dynamic
`is/isNot null`, `autogeneratedPrimaryKey`/`primaryKey` non-default-type arms. The independent critic still
judges the typed surface *essentially* mature (value-density is low and the items are mostly low–medium value),
but "saturated → stop" was an over-call: a clean-room sweep keeps surfacing a real per-symbol tail. Net: this
round's worthwhile output is the **NEW gaps in §1–§3 and §5** (cheap, real) plus the known **mechanical fan-out
tail (§4)**.

> Conventions when implementing (from the repo): pair dynamic-condition tests with their direct equivalent
> (identical SQL+params); date/time under `TZ=UTC`; some items need a new fixture column/helper (flagged); respect
> per-dialect `NOT-APPLICABLE`/`TODO[LIMITATION]` markers; no `src/` change from a test PR.

**1.2. `IfValueSource.or<IBooleanValueSource>` — the Boolean-collapsing `.or` overload** —

**1.3. Temporal `valueWhenNull(VALUE)` / `nullIfValue(VALUE)` — localDate/localTime/localDateTime + custom twins**

**1.4. `UuidValueSource` / `CustomUuidValueSource` `valueWhenNull`/`nullIfValue` on the uuid receiver** —

**1.5. `CustomDoubleValueSource.roundn<NumberValueSource>`** —

## §4. Connection-API fan-out tail (mechanical — needs new domain helpers)

These are `protected` factories closed only at the arms prior rounds happened to add; the remaining arms are real but
**mechanical per-arity/per-keyword homogenization**, low semantic value. One non-`int`/non-covered-arity helper closes
several rows at once.

- **4.1. `buildAggregateFragmentWith*` arities** — only Args@1 / MaybeOptionalArgs@1 / ArgsIfValue@2 exist; arities
  0/2-5 of each are missing (distinct `NAggregate` path). Biggest hole in this section.
- **4.2. `buildFragmentWith*` arities** — Args@{3,5}, ArgsIfValue@{0,3,4,5}, MaybeOptionalArgs@{0,4,5} never
  instantiated.
- **4.3. `arg` / `valueArg` keyword arms** — only int/bigint/string/uuid (`arg`) and int/string (`valueArg`); the
  boolean/double/temporal/custom*/enum/customComparable Argument branches are unasserted.
- **4.4. `subSelectUsing` / `subSelectDistinctUsing` multi-table arities 2-5** — every call site passes exactly one
  correlated table; the widened source-union arm is unverified.
- **4.5. Aggregate input value-types** — `sum`/`sumDistinct` over **customDouble**, and `average`/`averageDistinct`
  over **bigint / customDouble**, are never fed (only int/bigint/customInt/customComparable/etc covered).
- **4.6. `createTableOrViewCustomization` P1/P3/P4/P5** — low value. **P0 and P2 are COVERED** (`withSqlHint` +
  `forSystemTimeBetween`, the latter a 2-extra-param customization called with both params in an executed doc-code
  test across all 6 dialects — this *resolves* the round-3↔round-4 discrepancy: P2 is covered). The variadic
  param-plumbing path is therefore already proven; the remaining arities add no new transform.
- **4.7. `sequence().currentValue()` on bigint/customInt + non-int sequence keyword arms** — minor (emission is
  keyword-independent; `nextValue` typing is covered, `currentValue` only on the int sequence).

## §5. Dynamic conditions & dialect config

**5.1. `uuidStrategy` non-default branches on Oracle / MySql / MariaDB** —
([Oracle/MySql/MariaDB `*Connection.ts` + their SqlBuilder `_getUuidStrategy`](../src/connections/)) · **high** ·
the most valuable §5 item. A `withUuidStrategy(...)` runner helper EXISTS for each (`oracle/runners.ts:80`,
`mysql/runners.ts:81`, `mariadb/runners.ts:81`) but **no test invokes it** — only the default strategy is covered
(`'built-in'` Oracle, `'binary'` MySql, `'uuid'` MariaDB). SQLite has a full `config.uuid-strategy.test.ts`; the
other three dialects have none. Add the analogous test per dialect: Oracle `'string'` + `'custom-functions'`, MySql
`'string'`, MariaDB `'string'` — asserting the distinct emitted SQL (e.g. plain-text path vs `uuid_to_bin`/`bin_to_uuid`).

**5.2. Dynamic `is` / `isNot` with explicit `null`** —
[DynamicConditionBuilder.ts:152-156](../src/internal/DynamicConditionBuilder.ts#L152) · **high** · cheap. The builder
hard-codes `is`/`isNot` to survive a `null` value (null-safe distinct-from); `withValues({ col: { is: null } })` is
never exercised (0 matrix hits). Add it paired with the direct `.is(null)` equivalent (identical SQL+params).

**5.3. `FilterTypeOf` custom-temporal arms (`customLocalDate`/`customLocalTime`/`customLocalDateTime`) + `customDouble`** —
[dynamicConditionUsingFilters.ts:137-142](../src/expressions/dynamicConditionUsingFilters.ts#L137) · **high**. The
fixture columns (`releasedOn`/`cutoffTime`/`signedOffAt`, and `Money`/customDouble) exist but are never fed through
`dynamicConditionFor`/`withValues`; the sibling `customComparable`/`customUuid` arms ARE covered. (customInt's
value-source arm may be structurally unreachable — no filterable customInt column exists; flag, don't force.)

**Low / near-zero value (note, don't prioritize):** `FilterTypeOf` descriptor-string `'double'`/`'uuid'` arms
(functionally equivalent to the covered value-source paths); Sqlite `getDateTimeFormat(type)` per-type divergence;
`TableOrViewOf`/`LeftJoinOf` ALIAS-is-`any` arm (resolves to the same shape as the covered `''` arm).
